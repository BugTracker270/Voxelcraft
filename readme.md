# Voxelcraft

An original, desktop-browser creative voxel sandbox built with TypeScript, Three.js, and Vite. No Minecraft code, textures, branding assets, or sounds are included. This is a playable foundation, **not Minecraft feature parity**.

## Run locally

Use Node.js 22 or later and a modern WebGL2-capable desktop browser with hardware acceleration, keyboard, and mouse.

```sh
npm install
npm run dev
```

Open the local URL printed by Vite. Click **Create a new world**, then allow mouse capture. If capture is denied, click **Return to world**. Escape releases the mouse and pauses the simulation. Embedded hosts must allow pointer lock; opening the game in its own tab is recommended. Touch controls are not implemented.

```sh
npm run lint
npm run typecheck
npm test
npm run build -- --base=./
npm run preview
```

`lint` currently runs strict TypeScript unused-code checks, not ESLint or CSS linting. Serve `dist/` over HTTP(S); do not open `index.html` with a file URL. The relative production base supports subdirectory hosting such as GitHub Pages. No hosting/deployment or automatic merge is configured.

Top-level dependency versions are pinned. A package lock must be generated by `npm install`, reviewed, and committed before requiring reproducible `npm ci` installs. The editing environment cannot run a shell or generate a verified lockfile. The proposed CI workflow uploads its generated lock as a build artifact when available.

## Implemented scope

| System | Behavior |
| --- | --- |
| World | Seeded rolling terrain, sand lowlands, trees with deterministic cross-chunk canopies |
| Rendering | Exposed-face chunk meshes, frustum culling, bounded chunk cache, incremental mesh construction |
| Art | Original procedural pixel-texture atlas, directional face shading, fog, drifting block clouds |
| Lighting | Twenty-minute day/night cycle; time pauses in menus |
| Movement | First-person mouse look, normalized WASD movement, sprint, gravity, jump, substep AABB collision |
| Building | Six-block reach, DDA targeting, repeat mining/placement, protected bedrock, player-intersection prevention |
| Blocks | Eight unlimited creative hotbar materials; middle-click block picking |
| Feedback | Target outline, block debris, synthesized sound effects, coordinates, FPS diagnostics |
| Saves | One local browser save, 20-second autosave, pause/page-hide save, JSON import/export |
| Validation | Versioned saves, finite-number and bounds checks, file/edit limits, surfaced storage errors |
| Interface | Responsive title/pause screen, view-distance and sensitivity controls, sound toggle, keyboard focus states |

## Saving and limits

Local storage belongs to the current browser profile **and origin**. Switching ports/domains, clearing browser storage, or using private browsing can make saves unavailable. Export a JSON backup regularly. Starting a new world or importing replaces the single local save after a confirmation. Import validates completely before replacing that save; unknown schema versions are rejected rather than silently migrated. Importing then requires clicking Continue to capture the pointer.

World height is 64 blocks; horizontal coordinates are bounded to `-2047..2047`. Bedrock and the outer boundary cannot be edited. A world supports up to 50,000 distinct edited block positions. Saves store the seed and edit overlay rather than generated terrain. Evicted chunks regenerate with edits intact. Deleted natural blocks are explicitly retained as air edits. There is no migration from earlier game code because the original repository contained only an empty README.

## Architecture

| Module | Responsibility |
| --- | --- |
| `src/world.ts` | Deterministic seed/hash/noise, terrain and trees, block registry, chunk cache and edit overlay |
| `src/player.ts` | Renderer-independent player state, overlap checks, gravity and collision |
| `src/gameplay.ts` | Renderer-independent grid raycast and mining/placement rules |
| `src/storage.ts` | Pure save decoding/validation plus browser persistence adapter |
| `src/renderer.ts` | Three.js resources, exposed-face meshing, chunk streaming, lighting and effects |
| `src/main.ts` | DOM, application lifecycle, input, audio, save coordination and animation loop |
| `src/style.css` | Menu, responsive layout, HUD and focus styling |
| `tests/world.test.ts` | Terrain determinism, coordinate edges, chunk edits and save validation |
| `tests/gameplay.test.ts` | Raycast edges, placement safety, protected blocks and player physics |

Generated meshes and cached chunks are evicted outside the view neighborhood; GPU geometries are disposed on replacement. Chunk construction is synchronous but queued nearest-first with at most two builds per frame and a soft time budget. One expensive mesh can exceed that budget. There are no worker threads or greedy meshing yet. Performance has not been benchmarked on hardware; lower view distance on integrated GPUs.

## Verification status

Unit tests and strict checks are provided but **must be executed** before treating this release as validated. The authoring environment has GitHub file/PR access only, without a terminal or graphical browser. No manual playtest or performance claim is implied. Check the PR and GitHub Actions for the latest execution status. Workflow creation can be blocked by connector permissions; if it is absent, run the commands above locally.

### Required browser acceptance checks

| Check | Expected result |
| --- | --- |
| Start / pause / resume | Mouse captures after user click; Escape pauses and releases it |
| Movement | Walking, diagonal movement, sprinting and jumping are stable at different frame rates |
| Collision | No wall tunneling, floor sinking, or placement inside the player |
| Chunk seams | Trees render consistently and edits refresh both sides of chunk boundaries |
| Editing | Mining and placement use the highlighted face and respect six-block reach |
| Save/reload | Edits, seed, position, view direction, selected block and time restore |
| Export/import | A JSON backup restores the same world; malformed files do not overwrite a save |
| Storage failure | Browser quota/permission failures display an export recommendation |
| Lost focus | Alt-tab and hidden tabs clear movement and held mouse buttons |
| Graphics | No missing faces, flipped textures, WebGL errors or stale disposed meshes |
| Performance | Check FPS/chunk memory while exploring at every view-distance option |
| Deployment | Production build loads from a subdirectory over HTTP(S) |

## Deliberate omissions

This release is creative-only: no crafting, survival health/hunger, mobs, combat, water simulation, caves, ores, multiplayer, redstone, infinite world, mobile gameplay, or mod API. Settings are session-only. Accessibility is provided for menus and status feedback, but first-person visual gameplay is not screen-reader accessible. Those systems require separate designs, tests, profiling, and playtesting rather than claiming a full Minecraft replacement.
